# Track Plan: Quality and Maintenance Tooling Baseline

## Objective
Standardize Codecov, Renovate, Scalene, Vale prose linting, and Markdown style across the root coordination workspace and all owning subrepos, using repo-role-specific adoption rather than one-size-fits-all tooling.

## Current Audit Summary
- Vale: present in root and all checked subrepos.
- Markdown style: root has `.markdownlint.json`; subrepos do not consistently have repo-local markdownlint style files.
- Codecov: observed in `cli-legislation-nz`; not consistently present across corpus repos.
- Renovate: observed in `cli-legislation-nz`; not consistently present across corpus repos.
- Scalene: present in `corpus-law-nz`, `corpus-nz-hansard`, and `nlp-policy-nz`; not universal.

## Root-Owned Coordination Artifacts
- `conductor/templates/quality-maintenance-tooling-baseline.md`

## Baseline Decisions
- Vale is required throughout.
- Markdown style is required throughout for repos with Markdown.
- Renovate is required for each real GitHub repo unless an org-level config is documented.
- Codecov is conditional and should be adopted only where coverage artifacts are produced and meaningful.
- Scalene is conditional and should be adopted for Python data, ingestion, NLP, and performance-sensitive repos.

- `corpus-law-nz`: add markdown style and Renovate; confirm Codecov readiness; keep Scalene.
- `corpus-nz-hansard`: add markdown style and Renovate; confirm Codecov readiness; keep Scalene.
